# Contributing to Project Mars

Thank you for contributing to Project Mars. The project is intentionally split between
Rust crates and a small set of Node applications. Keep domain behavior in the
Rust workspace, keep UI behavior in the relevant application, and update the
documentation whenever a supported workflow or limitation changes.

## Development setup

Install the latest stable Rust toolchain, Node.js 26.13.1 (pinned in `.nvmrc`
and `package.json` `engines`), and pnpm 12.21.0 (pinned via `packageManager`).
From the repository root:

```bash
corepack enable
corepack prepare pnpm@12.21.0 --activate
pnpm install
```

The Node workspace contains:

- `@mars/desktop` — React/Vite frontend and Tauri shell (hosts both the
  Notebook and Lab product views).
- `mars-vscode` (`extensions/vscode`) — VS Code language and notebook companion.
- `@mars/landing` — Next.js static landing page with Markdown docs.

Project Mars ships two products from this repository: **Mars Notebook** (the
interactive notebook platform) and **Mars Lab** (Machine Learning in Rust —
CSV datasets to ONNX models via the `mars-lab` crate, the `mars lab` CLI, and
the desktop Lab view).

Turborepo coordinates package tasks and caches successful work locally:

```bash
pnpm run check
pnpm run build
pnpm run dev
```

Run a specific package task with a Turbo filter:

```bash
pnpm turbo run build --filter=@mars/landing
pnpm turbo run check --filter=@mars/desktop
pnpm turbo run check --filter=mars-vscode
```

The Rust workspace is validated independently:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Rust crates under `crates/` must maintain at least **80% line and function
coverage**. `make coverage` runs `cargo llvm-cov` over those crates with
`--fail-under-lines 80` and `--fail-under-functions 80`, so it exits non-zero
when coverage drops below either threshold. CI runs the same `make coverage`
gate; install `cargo-llvm-cov` before running it locally.

## Running applications

Run the desktop frontend in a browser:

```bash
pnpm --filter @mars/desktop dev
```

Run the native Tauri application:

```bash
cd packages/desktop
npm run tauri dev
```

Run the landing page:

```bash
pnpm --filter @mars/landing dev
```

Run the VS Code extension compiler:

```bash
pnpm run vscode:compile
```

## Installing from a local checkout

`scripts/sh/install-local.sh` builds the `mars` CLI from the working tree
(with stale-build detection) and installs it to `~/.local/bin`, then delegates
the desktop app and editor extensions to `scripts/sh/install.sh`:

```bash
./scripts/sh/install-local.sh            # CLI only (default)
./scripts/sh/install-local.sh --all      # CLI + desktop + all extensions
INSTALL_DIR=/usr/local/bin ./scripts/sh/install-local.sh
```

The CLI supports both products: `mars notebook …` for `.mars` notebooks and
`mars lab …` for dataset upload, training, job inspection, and ONNX export
(data persists to `.mars-lab-data/` by default; see `MARS_LAB_*` settings).

## Pre-commit hooks

Two hook systems are available; they complement each other.

### Husky + lint-staged (default, fast)

`pnpm install` activates Husky via the `prepare` script. The
`.husky/pre-commit` hook runs `pnpm exec lint-staged`, configured in the root
`package.json`. It formats only staged files:

- `prettier --write` for JS/TS/JSON/Markdown/CSS/HTML/YAML — each package's
  own `.prettierrc.json` (including the Tailwind plugin) applies per file;
  root-level files use the root `.prettierrc.json`.
- `rustfmt --edition 2024` for staged `.rs` files outside `vendor/`.

`.prettierignore` excludes `vendor/`, `pnpm-lock.yaml`, and generated
directories. This hook is fast and only touches staged files — it does not
replace CI checks.

The `.husky/commit-msg` hook runs `commitlint` (config in
`commitlint.config.mjs`) and enforces [Conventional Commits](https://www.conventionalcommits.org/):
`type(scope): subject` with a lower-case imperative subject, e.g.
`feat(cli): add mars notebook diff`, `fix(renderer): resolve data URIs`,
`chore(deps): bump tauri`. Merge and revert subjects generated by Git are
allowed through automatically.

### pre-commit framework (optional, comprehensive)

For the full validation suite, install the Python `pre-commit` framework and
enable its hooks:

```bash
pre-commit install
pre-commit run --all-files
```

These hooks cover file hygiene, YAML/JSON/TOML validation, `cargo fmt
--check`, Clippy, workspace tests, the desktop build, VS Code packaging, and
landing page checks. They are intentionally comprehensive and may take longer
than a typical commit.

## Tests and native validation

The desktop Playwright tests run against Vite and validate the browser editor
surface:

```bash
pnpm run desktop:e2e
```

They do not launch the native Tauri shell. Native launch, save/reopen, dialog,
and platform integration tests require a configured WebDriver/`tauri-driver`
environment and should be run on the target operating system.

## Architecture

Keep document management, execution, protocol, rendering, and UI logic in
their respective crates or application layers. Do not put persistence or
runtime behavior in React components.

Before submitting a change, update `README.md`, `AGENTS.md`, `docs/ROADMAP.md`,
or the relevant document when behavior or limitations change — including the
per-crate `AGENTS.md`/`README.md` files under `crates/` and
`packages/desktop/AGENTS.md` for desktop changes. Add focused tests for new
runtime, format, protocol, or conversion behavior.

When changing a public format or command:

1. Update the implementation and focused tests.
2. Update the relevant reference documentation.
3. Update an example or fixture when it improves discoverability.
4. Run the smallest relevant validation, followed by the baseline checks when
   the change crosses crate/application boundaries.

## Code standards

Project Mars uses explicit error handling, strong Rust types, and strict TypeScript.
Avoid `unwrap()` and `expect()` in production Rust code, and do not introduce
TypeScript `any`. User code must execute outside the desktop application
process.
