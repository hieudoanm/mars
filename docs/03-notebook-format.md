# `.mars` notebook format

## Design goals

The `.mars` format is an independent, JSON-based document format. It is not a
serialized compiler session and does not require Rust to parse or edit.
Documents should remain useful for Markdown review, source control, export,
and future language runtimes even when a particular runtime is unavailable.

Mars notebooks are UTF-8 JSON documents with `format_version: 2`:

```json
{
  "format_version": 2,
  "metadata": {
    "language": "rust",
    "dependencies": {
      "serde": "1"
    },
    "cargo_lock": null
  },
  "cells": [
    {
      "id": "stable-cell-id",
      "cell_type": "code",
      "source": "println!(\"hello\");",
      "metadata": {},
      "execution_count": null,
      "outputs": []
    }
  ]
}
```

Cell types are `code`, `markdown`, and `raw`. Version 1 notebooks are migrated
on load to version 2. Only code cells may contain
execution counts or outputs. Notebook validation runs before serialization and
loading. Saves use a sibling temporary file followed by rename.

## Document and cell invariants

- `format_version` is required and must be supported by the loader.
- `cells` is an ordered list.
- Every cell has a stable, unique ID.
- `cell_type` is one of `code`, `markdown`, or `raw`.
- Markdown and raw cells do not carry execution counts or outputs.
- Code outputs remain attached to their code cell.
- Metadata is JSON-compatible and may contain forward-compatible fields.
- Validation runs before loading into the runtime and before saving.

Cell IDs are stable UUID-backed strings. Notebook metadata preserves additional
JSON fields, including imported Jupyter metadata. Cell ordering is meaningful:
execution ranges, display order, and export order all follow the document list.

## Persistence and migration

Mars writes through a sibling temporary file and rename sequence rather than
overwriting the target directly. This reduces the chance of leaving a
partially-written notebook after a process or machine failure. The operation
does not replace the need for backups or source control.

`format_version: 1` is migrated in memory to the current version (`2`) when
loaded. A schema change must update the current-version constant, add an
explicit migration, update this document, and add round-trip tests. Unsupported
future versions are rejected instead of being silently downgraded.

The optional `metadata.dependencies` object declares Cargo registry
dependencies for Rust code cells. Keys are Cargo package names and values are
version requirements or inline Cargo dependency tables. When present, Mars
generates a temporary Cargo project for each execution and uses Cargo's normal
dependency resolution and cache. A successful CLI run stores the generated
`Cargo.lock` text in `metadata.cargo_lock`; subsequent `--locked` runs require
that lockfile to resolve successfully. `--offline` prevents registry access and
requires all dependencies to be available in the local Cargo cache.

Dependency values may be simple version requirements or inline Cargo table
specifications. Dependency names are validated before a manifest is generated.
The embedded lockfile is text stored in notebook metadata, so a notebook can
carry the exact dependency resolution used by a successful run. Lockfiles can
be regenerated by a normal run and enforced with `--locked`.

## Output model

Outputs are typed in the shared domain model. Standard variants include text,
errors, HTML, images, tables, LaTeX, chart specifications, and arbitrary
MIME bundles. A MIME bundle preserves multiple representations and associated
display metadata instead of selecting one value too early.

Image representations follow the Jupyter convention: binary image MIME values
such as `image/png`, `image/jpeg`, `image/gif`, and `image/webp` contain
base64-encoded bytes, while `image/svg+xml` contains the SVG document itself.
When multiple image representations are available, frontends prefer vector SVG
and fall back to the bitmap variants. Evcxr/plotters HTML containing an SVG is
promoted to an `image/svg+xml` MIME entry at the runtime boundary.

The desktop and VS Code notebook views render MIME bundles directly, and the
standalone HTML renderer embeds images as `data:` URLs so exports stay
self-contained. Unsupported representations remain preserved as fallback text
instead of being discarded.

The desktop may render rich outputs interactively using bundled frontend
libraries. Standalone HTML export uses a dependency-free renderer with
sanitized HTML and static fallbacks. Unsupported or unknown MIME values are
preserved safely, but preservation does not imply that Mars can execute or
visually render every MIME type.

## Jupyter compatibility

Mars preserves imported notebook metadata under `metadata.jupyter` and keeps
cell metadata on the corresponding Mars cell. Compatibility tests cover
format-4 markdown, code, and raw cells; execution counts; stream output;
errors and tracebacks; display metadata; HTML, LaTeX, table, chart, and image
MIME values; PNG/JPEG/SVG image variants; widget view/state data; and unknown
MIME bundles. The representative fixture is
`crates/mars-jupyter/tests/fixtures/jupyter-compatibility.ipynb`.

When a Jupyter output contains multiple MIME representations or display
metadata, Mars retains the complete `MimeBundle` so unsupported widget and
application-specific values survive import/export instead of being silently
discarded. Single standard MIME values without metadata continue to map to
their typed Mars output variants.

Mars does not execute Jupyter widget protocols, comm messages, or frontend
state. Widget MIME data is preserved as an opaque MIME bundle for round-trip
fidelity. Table outputs are preserved as HTML when exporting to `.ipynb`;
structured dataframe semantics are not inferred from arbitrary MIME payloads.

Jupyter metadata such as kernelspec, language information, display metadata,
and unknown notebook/cell fields are retained where the Mars model can
represent them. Import/export aims for safe, useful interoperability rather
than claiming complete equivalence with every Jupyter frontend extension.
