# mars-protocol — Frontend/Backend Message Types

Serde-typed wire protocol between clients (CLI, desktop) and the kernel. Depends on `mars-core`.

## Types

- `RequestEnvelope { id, request }` — `id` is a UUID v4 generated by `RequestEnvelope::new`.
- `KernelRequest` (tagged `type`, snake_case):
  - `Execute { source, timeout_millis?, language? }` — both optional fields default for backwards compatibility; `language` selects the runtime in multi-language `mars kernel serve` sessions.
  - `Reset`
  - `Status`
  - `Cancel` — acknowledged with `KernelResponse::Cancelled`; `mars kernel serve` honours it while an `Execute` is in flight.
  - `Variables` — live session bindings (`VariableInfo` wire struct).
  - `Diagnose { source }` — compile-check a candidate cell without committing it (`CellDiagnostic` wire struct).
  - `Input { text }` — one line to the running cell's stdin.
- `KernelResponse`: `Execution { outputs, execution_count, duration_millis }`, `Status { status, execution_count }`, `Reset { status }`, `Cancelled`, `Variables { variables }`, `Diagnostics { diagnostics }`, `Input`, `Error { message }`.
- `KernelEvent`: `StatusChanged`, `Output` — for future streaming/event channels.

## Rules

- Wire format is JSON, one message per line (see `mars kernel serve`).
- Any change to these enums is a protocol change: keep `#[serde(default)]` on new optional fields and never rename existing variants without a migration story.
- This crate must stay free of runtime/document dependencies — types only.
